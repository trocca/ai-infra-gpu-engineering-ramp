Orientation

Before any single technique makes sense, you need the shape of the whole thing: what happens when, and what comes back around.

New data arrives, the world drifts, requirements change. The training algorithm runs again, from the top, producing a new trained model that replaces the old one. A deployed model is never finished; it is only current.

Three stages, then, not two: training learns from examples, inference answers queries, and retraining repeats training as reality moves. Everything in this chapter sits somewhere on that loop — Part II on the arrow into training, Part V on the difference between the training and inference boxes, Part VI on how a real system chains several loops together.

Part II

From raw data to features

A model never sees the world. It sees the columns you hand it. This part is about making those columns say something.

2. What is a feature?

size_m² | bedrooms | age | city | price 90 | 3 | 12 | Berlin | €550k 60 | 1 | 35 | Leipzig | €220k FEATURES ↑ TARGET ↑

One usable input signal

A feature is usually one dataset column: numerical (size_m²), categorical (city), Boolean, text-derived, image-derived, or engineered from other columns. The target is the answer a supervised model learns to predict—here, price. A row of features plus its target is one training example.

3. Feature engineering: making the pattern explicit

Feature engineering

Turn raw facts into clearer signals

birth date→age debt ÷ income→debt ratio timestamp→rush hour?

The model sees exactly what you feed it. A derived feature that states the pattern directly (age instead of birth date) makes the pattern learnable with less data and a simpler model. The information was always there — engineering moves it from implicit to explicit.

4. Feature scaling: comparable units

Feature scaling

Put numeric features on comparable scales

standardize: x′ = (x − mean) / standard deviation min–max: x′ = (x − min) / (max − min)

Needs scaling: KNN, K-means, SVM, neural networks, PCA, regularized regression — anything built on distances, dot products or shared penalty strength.
Usually doesn’t: decision trees, random forests, gradient boosting — trees split on thresholds one feature at a time, so a feature’s scale never mixes with another’s.

Avoid data leakage: fit feature engineering and scalers on training data only; apply the fitted transformations, unchanged, to validation, test, and future data. If the scaler has seen the test set’s mean, your evaluation is quietly cheating. This rule returns in §14, where it bites harder.
Part III

Naming things precisely

Casual usage lets “linear regression” mean a family, a fitting procedure, a set of coefficients, and a prediction rule — all in one sentence. Separating those four is most of the conceptual work.

5. Model family, training algorithm, trained model

Model family
the shape of hypothesis you allow: “a line”, “a depth-5 tree”, “a 3-layer network”. Defines what is learnable.
Training algorithm
the procedure that picks one member of the family using data: gradient descent, ordinary least squares, tree splitting, Lloyd’s iterations.
Trained model
the chosen member—concrete parameter values (weights, split points, centroids), frozen after training. The artifact you save.
Inference algorithm
how the trained model answers a query: a matmul forward pass, a walk from root to leaf, nearest-centroid lookup.
Computational procedure
how the math actually runs on hardware: vectorized loops, GPU kernels, distributed workers. Same model, many possible procedures.
ComponentFor linear regression
Model familylinear functions of the input
Training algorithmordinary least squares, or gradient descent — same family, different procedures
Trained modelŷ = 5 + 2x — the coefficients, and nothing else
Inference algorithmsubstitute a new x into that equation: one dot product
Computational procedurea BLAS call, on a CPU or a GPU
“Procedure” and “algorithm” are the same word whenever they denote a defined sequence of computational steps — a training algorithm is a training procedure. The one term above that means something else is computational procedure, reserved here for the hardware-level realization: how the arithmetic is scheduled, vectorized and distributed, not what it computes.

Note what the table exposes: calling linear regression “an algorithm” is loose speech. It is a family, fittable by more than one algorithm, and the thing you deploy is a third object again.

6. Is training the same algorithm as querying?

No.

The named method is the model family. Training and inference are two different procedures that happen to share that name. Training learns parameters from examples; inference applies the frozen parameters to new input. They run different arithmetic, at different times, at wildly different cost.

FamilyTraining algorithmInference algorithm
Linear regressionleast squares / gradient descent finds the coefficientsone weighted sum
Decision treesearch for the splits that best purify the leavesfollow the already-learned branches
Neural networkforward pass + loss + backpropagation + optimizer stepforward pass only
KNNalmost nothing — store the examplescompute distances, find the K nearest, vote

The neural network row is the clearest case: inference is a strict subset of training. The forward pass is common to both; loss, gradients and the optimizer exist only during training and are gone at serving time. KNN is the pathological opposite — nearly all of its work moves to query time. That inversion gets its own treatment in §11.

“Query” is ambiguous — two different operations answer to it:
Inference (also called prediction): ask a trained model to produce an output for new input. This is the sense used throughout this chapter.
Retrieval: search stored data — a database, a vector index — and return matching records, possibly to feed them to a model afterwards. No model parameters are involved.
In machine learning, the unambiguous term for querying a trained model is inference.
Part IV

The learning paradigms

Textbooks list these as one flat set. They are not one set — some answer “what signal does the model learn from?” and others answer “which examples, when, from where?”. Sorting them onto the right question is the point of this part.

7. The two primary paradigms

🏷️ Supervised learning

Inputs come with known targets. The model learns to predict a number (regression) or a class (classification). Example: predict a house’s price from its size, age and city.

🧭 Unsupervised learning

Inputs come without targets. The model finds structure: groups, directions of variation, density, outliers. Example: group similar customers with no idea in advance what the groups will be.

8. Three more ways to get a learning signal

These sit on the same question as §7 — what does the model learn from? — and so they are genuine siblings of supervised and unsupervised learning.

🌗 Semi-supervised

A few labeled examples plus many unlabeled ones. Labels are expensive; structure in the unlabeled mass helps place the boundary.
Example: classify images when only some are labeled.

🪞 Self-supervised

The data labels itself: hide a part, predict it. Supervised machinery, no human labels.
Example: predict the next word in a sentence.

🕹️ Reinforcement

An agent acts, the environment scores it with rewards. Learns a policy maximizing long-run reward.
Example: train a game-playing agent.

9. Four axes that cut across all of the above

The distinction most lists get wrong. Active, online, transfer and federated learning are not alternatives to supervised or unsupervised learning. Each answers a different question entirely — and each can be combined with any paradigm from §7 and §8.
Which examples?

✋ Active learning

The model chooses which examples a human should label next — the ones it is most unsure about. Same supervised objective, fewer labels for the same accuracy.
Example: ask a radiologist to label only the ambiguous scans.

When is it updated?

🌊 Online learning

Data arrives as a stream; the model updates incrementally, one example or mini-batch at a time, and adapts as the world drifts. Contrast with batch training on a frozen dataset. This is §1’s retraining loop, run continuously instead of occasionally.
Example: adapt a fraud detector to new transaction patterns.

Where does knowledge start?

🎒 Transfer learning

Begin from a model already trained on a broad task, then fine-tune on your narrow one. Training does not start from random weights but from learned representations.
Example: fine-tune a general image model for medical scans.

Where does training run?

🤝 Federated learning

Training happens where the data lives — phones, hospitals — and only weight updates travel. Raw data never leaves the device. A deployment topology, not a learning signal.
Example: train a keyboard model across millions of phones.

10. Paradigms compose

Because §7–§8 and §9 answer different questions, a single real system normally occupies several at once. There is no contradiction in stacking them:

Signal  self-supervised pretraining on raw text
Starting point  + transfer learning — each stage begins from the last stage’s weights
Signal  + supervised fine-tuning on curated examples
Update cadence  + online updates as new data arrives

Four labels, one model, no conflict — because they describe the signal, the starting point, the signal again, and the cadence. §15 walks through exactly this stack as it is actually built.

Part V

Training vs. inference in practice

§6 answered the question in principle. Here is the same split carried through every model family you are likely to meet — including the two that break the pattern.

11. Model by model

ModelTraining does…Inference does…
Linear regressionfind coefficients minimizing squared errorone weighted sum per prediction
Logistic regressionfind coefficients minimizing cross-entropyweighted sum → sigmoid → probability
Decision treegreedily choose splits that purify the leaveswalk root→leaf following the input’s answers
Random foresttrain many trees on bootstrapped rows / random feature subsetsrun every tree, average (or vote)
Neural networkforward + loss + backprop + optimizer step, millions of timesforward pass only—matmuls with frozen weights
K-meansalternate: assign points to nearest centroid / move centroids to the meanassign a new point to its nearest centroid
PCAfind the directions of greatest variance (eigenvectors)project a new point onto those directions
KNNnothing—just store the data (“lazy learner”)find the K nearest stored points, vote / average
DBSCANgrow clusters from density-connected points; flag outliersno native predict; typically re-run or assign to nearest cluster

The usual asymmetry

Training is iterative and expensive; inference is a single cheap pass. This is why a model can cost millions to train and fractions of a cent to query.

The two exceptions

KNN inverts the trade — free training, costly queries. DBSCAN has no natural inference step at all: it clusters a dataset, it does not produce a predictor for new points.

12. Spotlight: polynomial regression

Still supervised (there is a target) and—surprisingly—still linear regression: the function is linear in the weights w. The curve comes from the features, not the model. It is Part II and Part III meeting in one example.

13. The two K’s are different K’s

K in KNN = neighbors consulted

Supervised. To classify a new point, look at its K nearest labeled points and let them vote. K=1: trust the single closest example. K=15: smoother, more democratic boundary.

K in K-means = clusters requested

Unsupervised. You declare up front “organize this data into K groups”; the algorithm places K centroids and carves the data around them. K is the number of buckets, not neighbors.

Same letter, unrelated meanings: one sizes a jury, the other counts buckets.

Part VI

Putting it together

Two cases where the pieces stop being separate topics: an unsupervised model feeding a supervised one, and the pipeline behind every large language model.

14. Unsupervised models can build features for supervised ones

1

→
2

→
3

A customer’s cluster membership (“segment 3”) or a row’s first few principal components are often stronger signals than the raw columns they summarize. The unsupervised stage is acting as automated feature engineering — §3, performed by a model instead of by you.

Same leakage rule as scalers: fit the K-means / PCA stage on training data only, then apply the frozen transformation to validation and test rows. An unsupervised step that has “seen” the test set leaks information exactly like a scaler would.

↻ And back around. New data, new preferences, new failure reports feed the next training run — §1’s retraining loop at industrial scale. Deployed models are versioned, not finished.

Every paradigm in Part IV shows up in this one pipeline: self-supervised pretraining does the heavy lifting, supervised fine-tuning aims it, reinforcement-style preference learning polishes it, and transfer learning is the whole premise—each stage starts from the previous stage’s weights. Inference is then pure forward passes: the training machinery (loss, gradients, optimizer) is gone, exactly as §6 predicted.
